# Импортированные стратегии: сборник kinlay0

Источник: [kinlay0/zapret2-discord-youtube-strats](https://github.com/kinlay0/zapret2-discord-youtube-strats),
пин-коммит `ce0cddc399f1ed1aed892df9c55c90e264877395` (2026-11-09, «ver bump2»).
Обновления апстрима сюда не подтягиваются автоматически: новый импорт —
осознанный пересмотр пина, а не фоновая синхронизация.

## Что здесь лежит

- 7 оригинальных `.bat` из сборника, байт в байт как у автора:
  DOUBLE FAKE (×3), SINGLE FAKE (×2), HOSTFAKESPLIT TS (×2).
  Это первая группа интеграции (новые техники); CIRCULAR, EXP, ALT14–16
  и остальные группы сборника сюда не входят.
- `LICENSE` сборника: MIT с тремя копирайтами (bol-van, Flowseal, kinlay0).
  Стратегии — компиляция работ сообщества (bol-van, Flowseal и другие),
  kinlay0 — собиратель и портировщик на zapret2.
- `translate.py` — транслятор, которым из этих .bat сгенерирован модуль
  `src-tauri/src/engine/imported_strategies.rs`. Перегенерация:
  `python3 translate.py` из этой папки.

## Как стратегии попадают в программу

Супервизор не запускает .bat и не качает сборник в рантайме. Аргументы
winws2 переведены в данные Rust-модуля один раз, при разработке:

- вырезана обвязка сборника: вызовы service.bat, `--wf-*` (корневые
  фильтры строит супервизор), `--ctrack-disable`, игровые секции
  gamefilter (у GUI свои игровые секции и Lua-режимы) и его `blobs.lua`;
- пути списков подставляет супервизор своими правилами (имена файлов
  совпадают 1:1: list-general.txt, list-google.txt, ipset-all.txt и т.д.,
  содержимое списков — наше);
- блобы регистрируются нашим механизмом `--blob=name:@file`, а не его
  blobs.lua (тот жёстко падает, если нет любого из 22 файлов);
- lua-init — наши стоковые zapret-lib + zapret-antidpi + zapret-auto
  (его lua/ — байт-в-байт сток zapret2 v1.0.7, тащить нечего).

Известное ограничение: Lua-режимы разделения трафика (строгий/игровой)
и игровые секции GUI к импортированным стратегиям не применяются — как
и к флагманской zapret2-ru-ultimate, их аргументы являются фиксированными
данными. Разделение по приложениям (winws2-split) применяется наравне
с остальными winws2-стратегиями.
