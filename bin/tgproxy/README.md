# `bin/tgproxy/` — Telegram MTProxy-mode sidecar (runtime-managed)

Этот каталог управляется приложением во время работы, а не сборкой.

## Что здесь появляется

| Файл | Откуда |
|---|---|
| `TgWsProxy_windows.exe` | Официальный релиз [Flowseal/tg-ws-proxy](https://github.com/Flowseal/tg-ws-proxy) — скачивается кнопкой «Скачать прокси» во вкладке «Telegram» |
| `manifest.json` | Записывается при скачивании: имя ассета, версия релиза, SHA-256, дата |
| `TgWsProxy_windows.exe.download` | Временный файл во время скачивания (удаляется при несовпадении хеша) |
| `TgWsProxy_data/` | Portable-окружение официального exe (`config.json`, `proxy.log`, маркер first-run) |

## Модель доверия

- Ассет ищется **строго по имени** `TgWsProxy_windows.exe` в метаданных релиза.
- Поле `digest` ассета **обязательно** (`sha256:<64 hex>`); без него скачивание отклоняется.
- Файл хешируется **потоково во время скачивания** (механика upstream `utils/update_check.py`);
  сверка — до перемещения в `TgWsProxy_windows.exe`; при несовпадении временный файл удаляется.
- SHA-256 **перепроверяется при каждом запуске** по `manifest.json`.

## Важно

- `*.exe` глобально в `.gitignore` — бинарник никогда не коммитится.
- В `TgWsProxy_data/config.json` приложение пишет четыре ключа
  (`host`, `port`, `secret` и `check_updates: false` — собственный апдейтер
  tray-приложения гасится, т.к. обновлениями управляет zapret2-gui);
  остальное exe дополняет из своих дефолтов.
- Digest релиза дополнительно сверяется с пином в коде (`PINNED_RELEASE_DIGESTS`
  в `tgproxy.rs`): тихо перезалитый релиз или новая версия upstream без
  осознанного обновления пина — отклоняются.
- Sidecar запускается **де-элевированным** (токен обычного пользователя через
  `CreateProcessAsUserW`, `platform/windows/deelevate.rs`) — прав администратора у него
  нет, хотя GUI работает elevated.
- Официальный exe — tray-приложение: его иконка в трее при работе — ожидаемо.
