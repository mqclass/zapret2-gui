# Бинарные payload-файлы (`bin/`)

Каталог содержит бинарные TLS/QUIC/STUN-блобы, используемые стратегиями обхода
в качестве поддельных пакетов (`--dpi-desync-fake-*`) и паттернов
(`--dpi-desync-split-seqovl-pattern`).

## ⚠️ Известные несоответствия имён (не переименовывать бездумно)

### `tls_clienthello_max_ru.bin` — SNI внутри НЕ max.ru
Распарсенный ClientHello в этом файле содержит SNI сервиса cookie-баннеров
**OneTrust**, а не `max.ru`. Имя файла историческое и вводит в заблуждение.

Почему файл НЕ переименован:
- имя зашито в пресеты (`src-tauri/src/engine/supervisor.rs`), документацию
  (`CONFIG_GUIDE.md`), шаблоны UI и — главное — в **пользовательские профили**,
  хранящиеся вне репозитория; переименование молча сломает их;
- как fake-payload блоб работает корректно: для десинхронизации важно
  содержимое пакета, а не соответствие имени.

⛔ **Не «чините» файл под настоящий max.ru**: значения
`--dpi-desync-split-seqovl=664` в пресетах подобраны под **текущий размер
этого файла** (664 байта). Замена содержимого без переподбора `seqovl`
молча сломает связку fake/multisplit для секции general.

### `tls_clienthello_sochi_park.bin`
Аналогично: SNI внутри принадлежит другому сервису. Используется только как
generic fake-payload, переименование не требуется.

## Связка «размер файла ↔ seqovl»
Значения `--dpi-desync-split-seqovl` в пресетах (`681` для
`tls_clienthello_www_google_com.bin`, `664` для `tls_clienthello_max_ru.bin`)
в точности равны размерам соответствующих файлов. При замене любого `.bin`
необходимо заново подобрать `seqovl` (см. `docs/ARCHITECTURE.md`).

## Списки доменов/диапазонов
Актуальные списки лежат в `bin/lists/` (используются движком). Копии в
`lists/` (корень) и `bin/windows-x86_64/lists/` — исторические дубликаты,
см. план унификации в отчёте аудита (`~/workspace/reviews/zapret2-gui/REVIEW.md`,
пункт С3). Не редактируйте копии вручную — правится `bin/lists/`.
